# 监听与恢复：离线原型

本模块提供守则及可执行模拟。没有后台监听、真实消息投递、系统通知或软件重启。生产接入需要项目目标、权限和预算确认及现场验证。

普通程序保存观察事实；独立恢复角色按需诊断。静默不证明卡死、心跳不证明业务成功。疑似无进展仅冻结当前任务新派单，保留在途工作；可靠停止接口和回执缺失时不能声称已停止。

Incident保持OPEN/RESOLVED。重复观察更新evidence_revision并去重；关键事实、严重度、身份或授权变化更新decision_revision。正确但旧的建议也不可执行。恢复依据按类别、登记验证与版本关联；任意exit 0不能解除其他问题。

信封先验证project/request/endpoint/token，再由静态授权策略判断结构化动作。只在明确允许范围内有界重查同一请求；耗尽后报告。SENDING/SENT/SEND_UNKNOWN等未决状态不因超时、升级或重启释放。Relay全局目标锁与本地模拟进程锁不同，绝不删除真实锁。

用户等待来源与有效期需核对；保留截止与等待区间。墙钟跳变和观察间隙标UNKNOWN，不推断休眠。未知429保持UNKNOWN_THROTTLE；只查询可在预算内退避。

监听自身崩溃与员工三轮修复分开。离线监督同轮次异常退出第三次停止模拟拉起并升级，正常退出/用户停止不计；只有显式健康验证或人工重置开始新轮次。生产时间窗口尚未定。先保存报告再模拟通知，送达未知不能声称架构师已知。监督升级独立于故障监听实例。

## 运行与测试

在技能目录运行（需要Node.js）：

```sh
node scripts/monitoring-sim.mjs --offline
node --test scripts/monitoring.test.mjs
```

命令自行在系统临时目录创建全新隔离目录，打印报告路径。恢复演示使用 `--offline --resume <上次输出目录>`；只接受工具创建的隔离目录。不能指定项目目录、真实请求目录或全局锁目录。残留模拟锁返回BUSY_UNCERTAIN，不自动清除。

输入为合成fixture，模拟时间而非真实等待；无网络或外部程序调用。state.json、events.log、INCIDENT.md与report.json只在临时根生成。重查默认3次/60秒是离线测试参数，不是部署授权。模型行为仍需后续真实验证。

## 决策与衔接规则

### 故障判断只凭静默或心跳

按任务登记业务里程碑/输出/命令结果与进程观察共同判读；静默/失联先标疑似或UNKNOWN，不能仅凭超时判崩溃。故障类别与解除标准随任务版本登记，能力缺失标未观测。

### 停止拉起与新请求冻结混同

三类生命周期分别记录：业务任务、模型请求、监听进程。程序重启仅恢复观测/对账，不自动发业务或诊断新请求；第三次异常按既有预算升级，用户停止不触发复活。计数重置依据和生产参数现场前明确。

### 报告持久化和送达证据缺分离

分别记录故障包可恢复位置、通知尝试、渠道回执、目标最终回复和故障解除。未知送达不释放请求/无限重通知；报告写入失败保存可用诊断且明确丢失范围，只有新证据或必要行动产生通知，不例行无变化报告。
