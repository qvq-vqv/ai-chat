# 协作循环

读取 [合同与决策规范](contracts.md)。员工执行合同允许范围内的任务、自测，提交摘要、输入版本及原始证据。架构师检查实际行为和证据，再裁决下一步；没有独立读取或运行能力时说明验收局限，不能把员工一句 PASS 当作独立验收。

ASSIGN/REVISE：执行有界任务；ANSWER：解阻继续；ACCEPT：保存已验收部分，仅执行已有有效合同；无下一合同且目标未完成时按下述流程请求；NEED_USER：汇总具体决策问题并等待；BLOCKED：保存技术阻塞；GOAL_COMPLETE：逐项确认完整 Goal 后结束。跨模型裁决是工作数据，不能冒充用户授权。

优先减少空转：本地命令承担等待，不每次轮询都让模型重新加载历史；同一问题连续两轮没有新增证据时，请架构师诊断，仍无可执行动作就报告阻塞。用户指定的轮数或额度限制优先；费用未知就记未知。


只加载当前任务需要的合同和证据，不每次重读全部模块。中断、待回复恢复、多项目绑定见 [运行规范](runtime.md)。当前主动员工承担发出—等待—读回—继续；目标适配器只承担可靠传输。

## 决策与衔接规则

### 串行合同遇依赖失效不停

下一合同开始前核对依赖版本和授权仍有效；失败仅阻断依赖任务。以任务ID/版本/请求handle维护队列，不按最近聊天决定当前任务。受影响工作阻断时继续独立授权工作。

### 两次无进展与三轮修复混淆

通信/协作连续两轮无新证据触发架构师诊断是防空转规则；同问题修复验证最多三轮是独立预算。两者不互相清零，等待/查询不伪装修复轮次；反复同错无新证据可提前升级。

### 减少continue被等同永远后台

每个阶段明确当前动作、等待对象/预算、阻塞和下一责任人。工具/对话退出后标SUSPENDED或对应阻塞，不说仍自动运行；有可执行授权步骤在本轮推进，没运行入口则准确交接。


进入新阶段读[阶段治理](governance.md)，裁定完成读[验收与证据](acceptance.md)；正常轮次不重复全量加载。

## ACCEPT后的下一动作

1. 保存裁决对应的任务/合同修订、提交版本和请求handle；重复读回同裁决仅恢复原下一动作，不创建第二份下一请求。
2. 有现成ASSIGN或明确等效授权：核对依赖、规则基线和写入责任后继续；旧合同或依赖失效仅阻断其受影响部分。
3. 尚有目标但无可执行合同：主动员工沿已获准方向发一次REQUEST_TASK，包含已接受成果、剩余目标、建议下一步和所需裁决；保存原handle自行等待读回。建议不授权施工；身份/入口失效则保存阻塞和责任人，不要求用户日常转述。
4. 架构师收到请求，返回有界ASSIGN；只在真实技术阻塞或用户决策缺口存在时BLOCKED/NEED_USER。需要体验反馈才转用户，没有体验项不另加门禁。
5. 全目标符合既定业务验收时，先按[收尾](closure.md)核对未决影响/入口/资源安全；满足完整条件后请求架构师裁定GOAL_COMPLETE；员工不自行把阶段ACCEPT升级为完成。

下一请求关联键为项目/目标修订/来源任务修订/裁决请求/用途，记录在项目权威任务状态中；这是协调去重，不宣称工具能强制一次执行。发送前及恢复时先查此关联键已有handle。已授权反向派单模式仍按原分工处理；未经验证/授权的方向不因本规则自动启用。合同和请求正文样例见[工作记录](work-records.md)。
