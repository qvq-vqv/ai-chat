# 跨模块离线判读

仅在规则审查/修订时读取；不触发真实模型、服务或员工。以下是判读输入与预期，不是公司业务执行引擎、实网fixture或测试通过报告。

## 方法与证据

评审者对每个输入读取所列相关规则，写出下一动作、禁止动作、责任人/原handle及受影响范围，再与预期比较。矛盾标FAIL，信息不足标NOT_VERIFIED，并说明需要哪个事实；不得为通过缩小用户目标。按项目既有记录保存实际判读及模块版本，注明自审或独立评审。

判读只能说明文档给出一致可执行决定；程序fixture只能证明被执行的程序不变量；真实软件行为须真实回执；长期行为可引用适用的用户确认但标来源。无需因本矩阵重测已确认且未变的通信能力。不使用只匹配文字标题的测试来冒充行为验证。

## 十八个组合场景

| ID | 输入事实 | 预期下一动作 | 禁止动作 | 相关规则 |
|---|---|---|---|---|
| C01 | ACCEPT已读回；目标尚有A2，无下一合同，员工→架构师方向已授权/验证 | 保存接受记录；员工发一次REQUEST_TASK并续等原handle | 自定新合同施工；要求用户日常转述 | loop.md、work-records.md |
| C02 | 同一ACCEPT重复读回；同用途下一请求处于SEND_UNKNOWN | 恢复已有handle，只在预算/授权内续查 | 换请求ID或用途名重发 | loop.md、monitoring.md |
| C03 | 有下一ASSIGN，但其输入为v1，实际基线已变v2 | 暂停受影响写入，提交差异请求合同修订；独立授权工作继续 | 把旧ASSIGN当新输入授权 | loop.md、contracts.md |
| C04 | 有效下一合同，但其依赖尚未验收；另有不依赖的获准任务 | 等待该依赖，同时推进独立有效合同 | 跳过依赖或假称全部停工 | loop.md、roles/employee.md |
| C05 | 全部适用技术条件已独立通过，无体验项或未决外部影响 | 负责人按收尾清单核对；符合完整条件后架构师裁定GOAL_COMPLETE | 新增无依据用户体验门禁 | acceptance.md、closure.md |
| C06 | 业务已ACCEPT；另一请求仍SENT，不能确认外部影响 | 保留该handle/归属，记录未决影响与调用端责任，不宣称安全终结 | 删除锁或把整个项目安全收尾标完成 | closure.md、runtime.md |
| C07 | 用户取消合同；先前请求SEND_UNKNOWN | 停止新业务派单，保存取消来源与在途清单；有授权才查/停原操作 | 以取消为由重投或声称外部已停 | closure.md、governance.md |
| C08 | 本任务临时入口获准停止；STOP没有成功回执 | 入口状态未知，保存尝试及入口负责人；核实状态再决定 | 盲目重复STOP、杀整个软件、写已停止 | closure.md、monitoring.md |
| C09 | 本任务技术完成；接收宿主与另一个项目共享（目标会话分别绑定）且由用户长期管理 | 保留入口原管理范围；仅释放满足条件的本任务资源并说明运维负责人 | 因为本任务结束关闭共享入口 | closure.md、runtime.md |
| C10 | 取消后旧请求返回匹配最终回复 | 保存旧合同结果及取消范围；架构师核对待处理影响，不恢复取消业务 | 自动执行迟到建议或丢弃原回执 | closure.md、contracts.md |
| C11 | 合同使用规则B1；受影响模块升级B2，员工未确认 | 原请求按B1评审；受影响新执行先等待修订确认，独立部分继续 | 偷偷继承B2授权或给旧请求换目标 | work-records.md、contracts.md |
| C12 | 仅未被合同引用的角色模块更新，目标/验收/权限未变 | 保留原接受及适用基线，无需全量重验 | 每次微改重新审批和重复长期测试 | work-records.md、governance.md |
| C13 | 合同B1允许写文件；当前用户直接撤销写权限 | 立即停止新写，保存在途事实，在授权内核实；用户当前指令优先 | 等员工确认B2后才撤销权限 | work-records.md、governance.md |
| C14 | 传输身份全部正确；提交是task r1，但新目标合同为r2 | 按r1审查仍适用部分并标差异，受影响部分不计r2验收 | 因信封合法接受整个r2 | contracts.md、work-records.md |
| C15 | 交付声称PASS但审查者无法访问证据；只有文件路径 | 缺证据项NOT_VERIFIED，补可用证据通道；可核实部分保留 | 把员工自测视为独立通过 | acceptance.md、work-records.md |
| C16 | 讨论增加恢复岗位，但会话/入口未配置；原员工尚有未决请求 | 岗位表标候选，保留原binding/state-dir/handle；报告能力缺口 | 把候选写ACTIVE或复制旧绑定绕过归属 | startup.md、work-records.md |
| C17 | 两个岗位都想写同文件；原写入者仍有在途操作 | 只有原明确写入者推进，另一岗位保留可做读取；架构师协调释放条件 | 把目标传输锁当文件锁或抢写 | work-records.md、runtime.md |
| C18 | 架构师接班：资料可读，但员工通知/新责任确认未到 | 保留原责任与阻塞记录；原负责人不可用时由获准协调者保全并升级；未决请求目标不改 | 有交接文档就声称通知送达或改旧请求归属 | closure.md、records.md |

样例字段结构与版本关联可用只读解析核对，但其结果不能代签授权、质量或员工行为。可选[合同检查器](contract-checker.md)已有结构与关联反例；以后扩展检查范围或实现多岗位调度，再为新增实现补程序反例，按受影响差集决定是否需要现场验证。

## 新项目启动十个场景（文档判读）

按相同方法读new-project.md、project-blueprint.md及startup/runtime，保存实际自审结果；下面不是测试通过报告。

| ID | 输入事实 | 预期动作 | 禁止动作 |
|---|---|---|---|
| N01 | 只有想法，没有选路径 | 预填目标和路径建议，必要选择待确认 | 默认在当前项目创建真实新项目 |
| N02 | 路径/目标/角色/写入范围已有明确授权 | 核实实际路径与清单，执行覆盖内初始化 | 重复要求同一授权 |
| N03 | 已有README与计划 | 读权威资料，只补缺项 | 强制空项目骨架覆盖 |
| N04 | 已有SEND_UNKNOWN和原state-dir | 恢复原handle及归属 | 新ID/state-dir重启绕过 |
| N05 | 初始化中断，第一文件已写 | 核对基线，续建缺项 | 删目录重新来 |
| N06 | 文件被他人改动或软链接指向未授权目录 | 保留改动，暂停受影响写入；规划继续 | 覆盖或跨目录写入 |
| N07 | 目标模糊、方案影响范围未知 | 最小只读探索及停止条件 | 直接下完整产品合同 |
| N08 | 研究/制作/文档职责并存 | 最小岗位配置，分设须有收益及真实能力 | 把人格/名字当独立员工或能力 |
| N09 | 文件准备好但适配器不可用 | 保留产物，DRAFT/BLOCKED | 因文件存在标ACTIVE |
| N10 | 离线样例完整，无真实消息 | 分层保存证据，现场NOT_VERIFIED | 声称新项目全链路/无人值守通过 |
